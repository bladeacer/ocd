# [0.7.0]

[Full release page](https://github.com/bladeacer/ocd/releases)

All notable changes to ocd in this version are documented below.

The format is based on Keep a Changelog, and this project adheres to
Semantic Versioning.

## Added

- Cache sweep engine in `internal/core/sweep.go`. `EnsureAllCSS` makes sure
  `app.css` is cached for a list of versions. It downloads the versions that
  are missing or expired, runs up to 8 downloads at a time, and reports
  progress as `[done/total] version: status`. The result is a `SweepResult`
  that counts cached, downloaded, unavailable, and failed versions.
- `core.ReleaseExists` probes a version with a HEAD request, so a sweep can
  learn that a version has no release without downloading anything. The sweep
  now probes every version first, reports the versions with no release, and
  downloads only the rest. About 10 of the 108 public desktop versions have
  no release, so this saves a wasted transfer for each of them.
- `core.ParallelFor` runs work across a bounded number of goroutines.
- Cache expiry. A cached `app.css` is reused for 14 days and downloaded again
  after that, because Obsidian can republish or correct a release. Set the age
  with `--cache-days` on `origin` and `check`, or with `cache_days` in config.
  A value of `0` disables expiry.
- `cache_days` config key (`internal/config/config.go`) with the
  `CacheDaysOrDefault` helper, which falls back to 14 days when the config file
  does not set the key.
- `--compat-sweep` flag on `ocd check`: cache `app.css` for every public
  desktop version before the compatibility check, so the check covers the whole
  public history. The flag is off by default, so `check` stays fast.
- `OriginResult.Scanned` field and a `searched:` line in the `origin` output.
  The result now says how many versions it actually searched, so a thin search
  is visible instead of silent. The field is in the TOML, JSON, and YAML
  exports.
- `--refresh` flag on `ocd extract`. The command now reports when a version is
  already cached and points to `--refresh` and `ocd clean <version>`.
- `core.CSSPath`, `core.CSSCached`, `core.CSSModTime`, and `core.CSSFresh`
  helpers for cache freshness checks, and `core.ExtractCSSForce` to download a
  version that is already cached.

## Changed

- `origin` now caches every public desktop version on demand before it
  searches. Before this change it searched only the versions that happened to
  be cached, so it reported the wrong answer whenever the cache was thin. For
  example, `--background-primary` was reported as introduced in `1.6.3` from 8
  cached versions. The correct answer is `0.5.0`, found across all 101 public
  desktop versions that have a release on GitHub.
- The version metadata cache in `diff`, `interact`, and `origin` now uses the
  same expiry as the CSS cache. It had no expiry before, so a stale RSS feed
  was used forever.
- `ocd extract <version>` no longer re-downloads a version that is already
  cached. Use `--refresh` to replace the cached copy.
- `app.css` is now written to a temporary file and renamed into place. A failed
  or interrupted download no longer leaves a partial file in the cache, and a
  failed `--refresh` keeps the copy that was already cached.
- A version with no GitHub release is reported as `unavailable` and does not
  stop the sweep. Callers match the new `core.ErrNoRelease` error with
  `errors.Is`. Those versions are probed again on the next run, so a release
  that appears later is picked up without any action.
- `origin` fails with a clear error when no versions are found, instead of
  searching nothing and reporting "not found".

## Fixed

- `ocd origin` no longer reports an introduction version based on a partial
  cache. This was the main defect: a variable that was missing from the cache
  looked like it was introduced much later than it really was.
- `ocd check --compat-mode` had the same partial cache problem. Run it with
  `--compat-sweep`, or run `ocd origin` first, to get a correct result.
- Sweep progress goes to stderr, so piping the `origin` result to a file no
  longer mixes progress lines into the output.

## Removed

- The deprecated `.air.toml`. Air reads `.air.toml` by default, so having both
  that file and `air.toml` meant bare `air` and `make watch` behaved
  differently. The remaining `air.toml` is the one `make watch` uses.

## Internal

- Test coverage is now 82.4%, above the 80% target in `AGENTS.md`. It was
  77.8% before this work.
