# [0.8.0]

[Full release page](https://github.com/bladeacer/ocd/releases)

All notable changes to ocd in this version are documented below.

The format is based on Keep a Changelog, and this project adheres to
Semantic Versioning.

## Added

- `ocd check` now accepts a folder as well as a single file. The command that
  you gave is the theme source:

  ```bash
  ocd check 1.6.3 ~/.config/obsidian/themes/flexcyon
  ```

  For a folder, every CSS file below it is read, with `theme.css` first
  because that is the file Obsidian loads:

  ```bash
  ocd check 1.6.3 ~/themes/flexcyon
  ```

- `core.ReadTheme` and `core.ThemeSource` collect the custom properties of a
  theme from any number of files, in source order, with names deduplicated
  across files. Noise directories such as `node_modules` and `.git` are
  skipped.
- `core.ParseCSS` and `core.CSSIndex`: a byte scanner for stylesheets, with
  `VariableList`, `HasVariable`, and `HasSelector` lookups.
- `core.NormalizeSelector` collapses whitespace in a selector, so a selector
  written across several lines matches one written on a single line.

## Changed

- `ExtractCSSVariables`, `ReadCSSVariables`, `ContainsSelector`, and
  `ContainsVariable` all use the new scanner. They read the same names as
  before for pretty-printed CSS, and now also read minified CSS.
- The `check` command reports where the theme variables came from, on stderr:
  `Theme: 640 variables from 2 css file(s) in <path>`.
## Fixed

- Minified themes were almost entirely unreadable. The variable reader matched
  only declarations that started a line, and minified CSS puts many
  declarations on one line. On the flexcyon theme, 13 of 640 custom properties
  were found before this change, and all 640 are found now.
- A quote escaped outside a string, as in the attribute selector
  `[data-task=\"]`, was read as the start of a string. In the flexcyon theme
  this swallowed 41 KB of the file and hid every declaration after it.
- Selector matching ignored attribute selectors, element selectors, and
  selectors written across several lines. The long selector
  `body .workspace-leaf.mod-active .workspace-leaf-content[data-type=markdown] .cm-gutterElement.cm-active`
  is now matched.
- A custom property whose value contains a semicolon, such as
  `--url: url(http://x/y;z)`, was cut short at the semicolon.
- `FindOrigins` reported a target as present in every version after the one
  where it was first found, whether or not it was really there. The versions
  list for each target was therefore wrong.

## Notes

- Only CSS is read. SCSS sources are not, because a Sass file defines its
  palette as `$variables` that are injected at build time, and those never
  reach Obsidian. Comparing them produced results that looked authoritative
  but were not.
- Build the theme first and point at the folder. That gives the result that
  Obsidian will actually load.
